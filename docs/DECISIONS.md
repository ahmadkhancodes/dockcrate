# Decisions

Standing decisions are in docs/factory/BATCH1_PLAN.md (Mongo instead of Postgres, Better Auth, Stripe first, Mailer interface, Vercel-first, keep 3 deployments).

## 5 Nov 2026 (Phase 0)
- **D-01 Verification tier without a Windows lab.** Vercel cannot run Windows VMs. A version reaches `verified_static` (hash, signer, scan, detection proven by rule check). Until `ProxmoxVmLab` exists it publishes to Pilot only, shows 3/4 and "VM test pending", Broad keeps 48 h delay and auto pause. `REQUIRE_VM_VERIFICATION=true` makes the VM check mandatory. Copy never claims a VM test that did not run.
- **D-02 Infra deviations from the workbook's zero third party rule**, owner approved in BATCH1_PLAN: Vercel, MongoDB Atlas, Cloudflare R2, a transactional mail provider, Vercel logs instead of self hosted GlitchTip/Prometheus/Loki. Each is behind an interface (`Mailer`, `LogSink`, `JobQueue`, `ObjectStore`). Egress allow list is enforced regardless.
- **D-03 Node `.intunewin` implementation.** IntuneWinAppUtil is Windows only and licensed for internal use, not hosted. We implement the Intune content encryption format clean room from Graph docs (AES-256-CBC + HMAC-SHA256, `fileEncryptionInfo`), no GPL code copied. Proven against a real tenant in M2 and against the Microsoft tool on the VPS lab.
- **D-04 Grace periods.** Over device limit: 14 days no hard stop. Payment failure: 14 days (FR-34), resolving the workbook's 7 vs 14 oddity in favour of the FR.
- **D-05 Group creation.** The three permissions do not include `Group.ReadWrite.All`. MVP: pick existing groups plus instructions. "Create DC-Pilot/DC-Broad" is an optional separate consent via a second app registration, only if the owner asks.
- **D-06 EAM checker** is a three question self check page, not a Graph read, because `subscribedSkus` needs a permission outside the three.
- **D-07 Auth.** Better Auth with the Microsoft provider on the `organizations` authority, personal MSA tenant `9188040d-6c67-4c5b-b112-36a3c8b1b0b4` rejected; magic link disabled for sign in. Owner rule says Auth.js in the workbook; the batch standing decision (Better Auth) wins.
- **D-08 Design overrides of the playbook** (recorded in DESIGN.md): dark backgrounds `#15191C/#1D2327` instead of the whitelist; Big Shoulders + Atkinson + Plex Mono instead of Geist/Manrope; weight 800 max; no hero heading gradient.
- **D-09 Fleet annual price** is not in the workbook; use 10x monthly ($999.90/yr) from "annual = 2 months free". Education price is a separate hidden Stripe price ($34.99/mo) granted after manual approval.
- **D-10 Catalog scope.** A reviewed `catalog/top200.json` bounds winget ingestion; unknown installer types go to `manual`, never guessed. The public catalog count shown is always the real verified count.
- **D-11 Kit adoption.** PlanIds are free/starter/professional/business/fleet; meters are devices, tenants, catalog_apps, custom_apps with `UNLIMITED = 1_000_000` for uncapped tenants/catalog (no Infinity: entitlements are JSON). Fleet annual $999.90 per D-09; education price is `educationUsd` on Professional (no Stripe price in the kit catalog). Packer lives at `src/lib/intunewin` with `fflate` 0.8.2 added to root deps; `packages/` removed. `docs/**` added to ESLint ignores (design tooling scripts). Marketing copy still says Postslot-era wording in places; M1-B rewrites it.

## 5 Nov 2026 (M2)
- **D-17 Pilot only until a lab exists.** The task and D-01 win over the ARCHITECTURE line that Broad promotion "keeps the 48 h delay": a version with the VM check pending (3/4) is publishable to Pilot only, and `ring-tick` never promotes it (the dock shows "Pilot only"). Broad needs 4/4. `REQUIRE_VM_VERIFICATION=true` holds the version entirely. Pilot failure pause still applies to Pilot only versions.
- **D-18 Stub mode.** With no `ENTRA_CLIENT_ID` the app runs in stub mode: the email link sign in plugin is registered (local dev and e2e only), Graph is the in-memory `FakeGraphClient`, and the placeholder installer is packaged. With Entra configured the magic link plugin is not registered at all and the real `RealGraphClient` is used. The manifest key may be ephemeral only on the memory driver.
- **D-19 Roles.** Better Auth roles are now owner, admin, operator, viewer (the kit's `member` is renamed `operator`). Operators publish and roll back but cannot connect tenants or edit rings. Tenant scope lives in `memberships_ext` (`all` or a list); owners and admins always see every tenant. One `authorize()` in `src/lib/authz.ts`. The scope editing UI is M4.
- **D-20 Domain storage.** A tiny generic `Db.collection<T>(name)` (get, find by equality, put, delete) holds tenants, catalog, catalog_versions, deployments, ring_configs, tenant_apps, org_settings, alerts, memberships_ext (Mongo collections prefixed `dc_`). The workbook's richer model is mapped onto it; indexes in `ensureIndexes`.
- **D-21 Catalog seed.** `src/content/catalog-seed.json` holds the 6 sample apps; the `catalog` collection is seeded from it on first read and each version is signed (Ed25519) and gets a verification record with 4 checks and a QA log. Hashes, signers, product codes and dates are illustrative (D-12). The seeded Acrobat row is `held` for a changed signer. The winget sync and the real downloader/scanner (Sandbox) are still not built; `verifyVersion` takes their evidence as input and is unit tested with EICAR, stale signature, hash and signer cases.
- **D-22 Consent mechanics.** The callback verifies inline with `GET /organization` (so Connected shows within seconds) and the `tenant-verify` cron retries while waiting; the connect page polls for up to 2 minutes. A transient Graph error never disconnects a connected tenant; only a consent error does (alert plus audit). Ring setup UI and group picking UI are M3; the API (`POST /api/rings`, `GET /api/tenants/:id/groups`) exists.
- **D-23 Rollback target.** Rollback restores one of the last 3 earlier deployments of the same app and tenant (default the previous), re-assigns it with the intent it had (Required by default) for the rings the current version reached, assigns the current version Uninstall there, marks it `rolled_back` and writes `deployment.rolled_back`.
- **D-24 Real tenant proof still pending.** Everything Graph related is proven only against `FakeGraphClient` and a stubbed `fetch`. The upload sequence, the `.intunewin` acceptance by Intune and the Azure block upload have not run against a real tenant (MANUAL_STEPS 1, 3, 5 and the test tenant). The Graph endpoints and payload shapes are written from the documentation and may need fixes in the spike.

## 5 Nov 2026 (M3)
- **D-25 Ring config is validated against the tenant's real groups.** `POST /api/rings` reads the tenant's groups and takes names from Graph, never from the client. Pilot and Broad must differ, delays are whole hours 0 to 720 with Broad not shorter than Pilot, threshold 1 to 100. `autoUpdateDefault` (default on) is the starting auto update value of a newly published app in that tenant.
- **D-26 App Sets.** Professional and above (the plan table lists App Sets there); Free and Starter publish app by app. A run is one record with a result per tenant (apps published, error, attempts); tenants run 3 at a time, apps within a tenant in order, and the record is saved after each tenant so the progress view can poll. A tenant level failure (not connected, paused, rings missing, device grace ended) fails its remaining apps with the same reason. Retry re-runs only failed tenants; publishing is idempotent per tenant and version. The run executes after the response (`after()`); on a long run the 60 s function limit applies, which a VPS worker removes later.
- **D-27 Device counting.** `DeviceCounter` is the interface. Until a Graph managed device read exists, `InstallDataDeviceCounter` takes the largest install result count (installed + failed + pending) across a tenant's published apps, a lower bound of the devices that received DockCrate apps. Counts are stored per tenant (`device_counts`); the org total is the sum.
- **D-28 Limits and grace.** Limits come from `product.ts` through the effective plan, read live. Tenants and apps are hard limits at the moment of adding (402 `limit_reached`). Devices are a soft limit: going over starts a 14 day grace (D-04, clock stored in `org_billing.overSince` by the nightly job, shown by `orgLimits` even before the first night), then publishing stops (402 `device_grace_ended`); existing deployments, rollback and rings keep working. Dropping under the limit or upgrading clears it at once. Banners show at 80% ("close") and 100% ("reached"); above 100% they name the grace end date. The apps meter counts distinct apps with a tenant app record in the org.
- **D-29 Audit.** The log stays append only (the `Db` interface has no update or delete). `audit()` now records the client IP from `x-real-ip` or the first `x-forwarded-for` hop when called inside a request; jobs record none. CSV export covers the whole filtered log (paged, capped at 20,000 rows), UTC times, actor id or "system", and prefixes cells starting with `= + - @` with an apostrophe against spreadsheet formula injection. Showing user emails instead of ids and the hash chain are M4.
- **D-30 Verification pipeline.** `WingetSource`, `InstallerDownloader` and `Scanner` are interfaces with fakes only; the scanner also reports the signer thumbprint because both come from the same Sandbox read. `verifyVersion` accepts evidence or `{ downloader, scanner }`. `catalog-sync` runs every catalog app through winget, download, scan and verify, but with fakes it persists nothing (a fake run must never mark a version verified). With persistence on, a newer winget version is saved as a candidate with no detection rule, so it cannot publish until the rule is reviewed (D-10), and only becomes the app's current version once it reaches verified_static.
- **D-31 Crons.** `vercel.json` now has `rings-tick` (every minute, needs Vercel Pro; the Cloudflare worker is the alternative on Hobby), `device-count` (02:30 UTC) and `catalog-sync` (04:00 UTC) next to `webhook-retries`. `tenant-verify` is not scheduled yet.

## 5 Nov 2026 (M4)
- **D-32 Alert routing.** `raiseAlert` (src/lib/alerts) stores the alert (the in-app centre reads it) and emails each member by `routeAlert(alert, prefs, scope)`: out of scope tenants get nothing; critical always shows in-app and is emailed at once unless the user turned email off; info and warning follow the in-app preference, tenant mutes and the daily digest (`alert-digest` cron, 07:00 UTC). Preferences are per user and org (`alert_prefs`); the row is created when the bell first loads, so a member who never opened the app gets no email (known gap; recipients are not read from Better Auth). The ring config's alert email still gets ring alerts, deduped. Acknowledgement is shared by the org. `dedupeKey` keeps cron repeats to one alert. Consent revoked found by the ring tick now uses kind `consent.revoked`; the tenant-verify path keeps `tenant.disconnected`.
- **D-33 Triggers.** `device.grace_ending` fires from the nightly device-count job 3 days before publishing stops and once more when it stops. `signer.changed` fires from catalog sync (`onSignerChange`) to every org that has the app published.
- **D-34 Scope editing.** `updateMemberScope` is owners and admins only, for operator and viewer roles, refuses an empty list and foreign tenants, and audits `member.scope_changed`. Role and invite UI was already there from M1.
- **D-35 Audit hash chain.** Per org `seq`, `prevHash`, `hash` (SHA-256 over canonical fields). Mongo appends with a unique `{app, orgId, seq}` index and retries on conflict. Older entries are "legacy". Limit stated on the security page: deleting only the newest entries is undetectable without an external anchor (export or later a signed head). `POST /api/audit/verify` is owner/admin.
- **D-36 Demo label.** A catalog version with no vendor installer URL is "Demo data" in the public catalog; the real pipeline sets the URL so the label drops by itself. Seed apps gained a `category`.
- **D-37 DPA download.** `/api/legal/dpa?download=1` renders the same DPA text as standalone print friendly HTML with Annex 1 built from `product.subProcessors`; a test keeps it, the sub-processors page and product.ts identical.
- **D-38 Fix.** `formatDate` moved to `components/app/format.ts`: the audit and MSP server pages imported it from a client module and crashed at render.

## 5 Nov 2026 (M5 review, see docs/REVIEW.md)
- **D-39 No account linking.** Better Auth account linking is off. Entra's `email` claim is tenant controlled (nOAuth), so a Microsoft account is only ever its own user; a second account with the same email is refused.
- **D-40 One Microsoft tenant, one organization.** The consent callback never rebinds a row to another Microsoft tenant and refuses a Microsoft tenant already bound in another DockCrate org (audit `tenant.consent_conflict`, critical `tenant.claim_attempt` alert to the owner). An MSP and its customer cannot both connect the same tenant; support handles that case. Proof of tenant admin via an OIDC `tid` check is the planned follow up (REVIEW P1-1).
- **D-41 Retire per ring.** When N+1 is assigned to a ring, earlier live deployments of the app in that tenant lose that ring's group (Intune does not uninstall on unassignment). With no group left a deployment is `superseded`: the tick ignores it, it stays a rollback target.
- **D-42 Rollback is gated.** The target must pass `publishPlan` now; a Pilot only target is refused when Broad must be restored. The target keeps its remaining groups.
- **D-43 Publish lease.** One publish call per deployment at a time (5 minute lease, 409 `publish_in_progress`); not atomic yet (REVIEW P1-2).
- **D-44 Gates apply to automation.** Org pause blocks manual publish too; fan out goes through `assertCanPublish`; an unsigned installer fails the signer check; scoped members see only in scope audit entries; `tenant-verify` runs every 15 minutes; `/api/health` returns 503 when the database read fails.
- **D-45 Claims.** Public copy states the gate (no publish before hash, signer and scan pass; VM pending is Pilot only) and calls the scanner and VM lab "being commissioned" until real adapters exist. Sub-processors name Resend and Cloudflare.

## 6 Nov 2026 (P1 closure, see docs/REVIEW.md)
- **D-46 Consent proof by Entra sign in.** The consent redirect no longer binds a tenant. It sends the browser to that tenant's own authorize endpoint (implicit `id_token`, `form_post`, `prompt=select_account`, nonce in the signed 1 h state); only an account of that tenant can complete it. We verify the RS256 signature against the tenant's JWKS ourselves (no new library), then `tid`, `iss`, `aud`, `nonce`, `exp`, and an admin role id in `wids` (Global, Privileged Role, Application, Cloud Application Administrator). Cross-org and rebinding checks run again at the proof step. Required only when Entra is configured (`deps.requireConsentProof`, set by `defaultDeps`); stub mode keeps the old direct path because it only ever talks to the fake Graph. Residual: an admin lured into a link built for someone else's row would bind their tenant to that row's org; this is the same trust as the consent itself and the emailed link.
- **D-47 Atomic publish guard.** `Collection` gained `insertIfAbsent` and `claim` (compare-and-set). Deployment ids derive from `tenant:version:variant`, so the first insert is the guard; resuming claims the exact lease value it read. This replaces the read-after-write lease of D-43.
- **D-48 Orphan handling.** The Intune app id cannot be saved in the same instant as the Graph call, so a `createStartedAt` marker is stored first and the app is found again by its exact `DC | name` (`findAppsByName`). `publish-reconcile` runs every 10 minutes; uploads stuck for 10 minutes are resumed, duplicates with our exact name that no deployment records are deleted, uploads older than 24 h are abandoned (app deleted, deployment `failed`).
- **D-49 Download limits.** 400 MB, 45 s, HTTPS only, same host redirects only (max 3), manual redirect handling. These are constructor options so the real downloader can tighten them.
- **D-50 Alert rows at join time.** Preference rows are written by Better Auth organization hooks; first open stays as a fallback.
- **D-51 Focus and control tokens.** `--focus` light is dark amber (#9a5b00), `--text-muted` and `--warning` darkened, and a new `--control-border` token carries input edges. Contrast is asserted over the real tokens in `tests/unit/a11y.test.ts`.

- **D-52 Auto indexes.** `scheduleIndexes` (mongo.ts) runs `createAllIndexes` once per instance after the first connection, never awaited, never during build; index option conflicts (85/86) and other errors are logged and retried on the next cold start.
